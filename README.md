# 応募者・採用進捗ボード

## 概要

社員30〜100人規模の会社で、兼務の採用担当者1〜2人が使う軽い採用進捗ボードです。「応募者を待たせない」「面接評価をその場でまとめる」「辞退理由を数字で振り返る」に絞っています。

## 主な機能

### ボード・連絡期限

応募・書類選考・面接・内定の4列と、折りたたみ式の終了一覧。ボタンで段階を進め、連絡内容や辞退・見送りの理由を記録できます。職種と期限状態で絞り込み、最終連絡からの日数や期限切れを表示します。スマートフォンでは段階タブで切り替えます。今日やること画面には連絡期限と今日・明日の面接を集約します。

### 面接評価シート

5項目を1〜4の4段階で評価し、一言コメントと総合判断を面接官ごとに保存します。2段階以上の評価差を強調し、印刷時は選択した面接官のシートをA4縦1枚にまとめます。同じ面接官の再保存は評価の更新になります。

### 辞退・見送りの振り返り

理由の件数・割合、辞退段階、平均日数、理由と段階のクロス集計、連絡期限遵守別・職種別の辞退率を表示します。理由・段階・日数は期間内の終了者、辞退率は期間内の応募者全員（進行中・承諾済みを含む）が対象です。未遵守は過去の期限超過または現在の期限切れを意味します。因果関係を示す集計ではありません。CSVはUTF-8 BOM付きで、数式として解釈される先頭文字を無害化します。

## 日時と営業日の扱い

- 日付は `YYYY-MM-DD`、時刻は `HH:MM` の日本時間で保存します。
- マウント後に現在時刻とlocalStorageを読み込むため、サーバーとブラウザの日時差によるhydration不一致を避けます。
- 土日、日本の祝日（2025〜2027年、振替休日・国民の休日を含む）、12月29日〜1月3日は休業です。対象年以外の祝日は未対応です。
- 営業日数は起算日の翌日から数えます。連絡記録と段階移動で次の期限を計算します。設定変更は次の操作から適用します。
- 期限は日付単位、最終連絡・滞留・辞退までの日数は暦日単位です。
- 操作の記録時刻は現在の1分前に丸め、シードの記録は前日以前に生成します。面接予定は10:00〜18:00です。デモの直近2件は休日を含め翌日に設定し、それ以外は営業日に調整します。
- デモでは開いた日の期限状態を比較できるよう、休日にも今日期限の例を含めています。通常操作の期限は営業日で生成します。

## 画面一覧

| パス                         | 内容                                     |
| ---------------------------- | ---------------------------------------- |
| `/`                          | 進捗ボード                               |
| `/today`                     | 今日やること                             |
| `/candidates`                | 応募者一覧・追加・CSV                    |
| `/candidates/[id]`           | 詳細・編集・段階履歴・連絡記録・面接予定 |
| `/candidates/[id]/scorecard` | 面接評価入力・比較・印刷                 |
| `/insights`                  | 辞退・見送りの振り返り・CSV              |
| `/settings`                  | 連絡期限・面接官・職種                   |
| `/backup`                    | JSONエクスポート・検証付きインポート     |
| `/about`                     | デモの説明・既定データの再生成           |

詳細データはクライアントでlocalStorageから取得します。追加した応募者のIDも開けます。通常のNext.js配信では未知のIDも動的に配信します。静的配信に切り替える場合は、未知の `/candidates/*` を `404.html` にフォールバックするホスト設定が必要です。404ページ内でURLから詳細・評価画面を復元します。単にHTMLファイルを配置するだけでは未知のURLを解決できません。

## データの保存先

ブラウザのlocalStorage、キーは `apb:v1` です。認証、DB、メール送信、外部連携はありません。ブラウザや端末を変えても同期しません。壊れた保存データは通知して既定データに戻します。保存容量不足などで書き込めない場合は通知し、JSON保存を案内します。JSONインポートは構造を検証してから置き換え確認を表示します。

## 技術スタック

Next.js 16（App Router）、React 19、TypeScript、CSS、Tailwind CSSビルド環境、ESLint、Prettier 3。新規の実行時パッケージは追加していません。純粋関数のテストはNode.js標準のtest runnerと既存のTypeScriptコンパイラで実行します。manifestと本番のみ登録するService Workerを備えています。Service Workerは個人情報を含むレスポンスをキャッシュせず、オフライン表示は提供しません。

ロジックは `src/lib/`、部品と画面は `src/components/`、ルーティングは `src/app/` に分離しています。

## ローカル起動方法

Node.js 24以降を推奨します。このプロジェクト直下で実行します。

```sh
npm install
npm run dev
```

http://localhost:3000 を開きます。本番起動と品質確認：

```sh
npm run lint
npm run typecheck
npm test
npm run build
npm start
```

整形：

```sh
npx --yes prettier@3 --write "src/**/*.{ts,tsx,css}" "tests/**/*.js" README.md
```

テストでは営業日計算、期限・滞留、段階移動、評価差、辞退集計、CSV、バックアップ、複数日時でのシード生成を検証します。

## デモデータについて

応募日時は日中・昼休み・夜と休日を混ぜ、週明けや掲載直後の集中、1週間以上の空白を含めています。経路は固定シードの疑似乱数と職種別の重みで選び、連続4件の同じ並びを避けています。応募者メモは45名中23名に個別に記載し、連絡記録・評価・終了メモも重複しない内容です。保存済みのデータに反映するには「デモの説明」から既定データを再生成してください。

会社「みなと通商」、45名の応募者、3職種、5名の面接官はすべて架空です。日付は初めて開いた日、または既定データに戻した日からの相対で生成し、実在の企業・個人とは無関係です。選考中14名、期限切れ3件、今日期限2件を含みます。連絡期限を守れなかった応募者の辞退率が高い傾向と、面接官の評価が割れる例を含めています。通常の再訪では保存済みの日付を維持するため、時間の経過に伴い期限切れが増えます。
